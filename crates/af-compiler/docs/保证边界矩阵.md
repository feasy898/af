# 保证边界矩阵（G2a 交付 · ADR-010 义务一）

- 版本：v0.1（2026-10-24，G2a 随 IR schema v1 一并交付）
- 义务来源：ADR-010 §2「严格区分三种保证 + 可信计算基」——**完全接受，立即执行**。本文是该裁决的落文：每条 L0/L1 保证标注三类之一（可拆层），附 TCB 四行表。
- 范围界定：本文标注的是 **AFB（DSL + 编译器 + 执行面）体系自身的保证**；「AFB vs 通用组合基线」的对比矩阵是 G5 报告义务（ADR-010 §1），不在本文。

## 0. 三类保证的定义

| 类 | 定义 | 违例时的行为 | 证据形态 |
|---|---|---|---|
| **静态可证明** | 编译期（af-dsl 校验 + af-compiler lowering）由确定性算法判定，不需运行任何用户代码 | 拒绝编译，稳定错误码点名（E 码表，ADR-007 §3） | 错误码 + 反例测试（码集精确断言） |
| **运行时可强制** | 执行面在运行时以机制强制（拦截/熔断/终态化），违例被类型化上报，不静默降级 | 运行时拦截：节点终态化（budget_exhausted/stopped/…），事件留痕 | 落地契约 §5/§6 的既有机制 + trace/MES 事件 |
| **依赖可信组件** | 保证成立的前提是某组件**按声明行事**——该组件进入可信计算基（TCB），AFB 只能记账与核对声明面，不能验证其内部 | 组件失约时保证失效；AFB 的义务缩为「失约可归因」（记账/digest/血缘） | 注册表 digest、L4 逃逸记账、effect_class 声明 |

一条保证可拆多层（如 INV-1：声明面静态可证明，装配忠实性依赖执行面）——**拆层标注是本文的核心诚实手段**，不把多层保证压扁成单标签。

## 1. L0 不变量（四条，af-dsl M1-M4 已实现静态判定）

| 保证 | 标注 | 判定/强制点 | 证据锚点 |
|---|---|---|---|
| **INV-1 上下文完整性**（agent 的全部输入经 `context.sections` 声明：来源可解析、配额必填、store 读经视图策略） | **静态可证明（声明面）**：E2301 来源可解析、E2302 配额非正、E2303 LLM 节点直读 store、E2304 入边端口恰被一节引用、E2401-E2403 策略域/形参/模板变量——编译期全判。**装配忠实性依赖可信组件（执行面装配器）**：运行时确实按声明装配、不夹带未声明内容、配额不超——AFB 无法从 IR 证明，只能要求执行面把装配结果落 trace 供事后审计 | 静态：af-dsl `validate/inv1.rs`；运行时：执行面装配器 | af-dsl M2（RESULT-M2）；ADR-010 §2 预判「INV-1 上下文装配=静态可证明声明面、装配忠实性依赖执行面」 |
| **INV-2 写入串行化**（每个 store 恒单写者；无并发写冲突） | **静态可证明**：E2311 多写者/写者集合不符、E2312 map 体写体外 store（N 并行实例=N 写者）——编译期判定。**性质/机制分层**（ADR-010 §4）：保证的性质=「无并发写冲突」；v0.1 的机制=「单写者」（集中式形态的最简可判定形式）。机制多元（声明式原子合并协议）是 v0.2 高优议题，由 AutoGen relay 改写、Agensh 共享板两个翻译痛点实证驱动 | 静态：af-dsl `validate/inv2.rs`；运行时无强制需求（静态已排除多写者；执行面按 writer 路由写请求是顺从而非强制） | af-dsl M1；ADR-010 §2 预判「INV-2 写者唯一=静态可证明」、§4 裁决 |
| **INV-3 生成器-验证器分离**（验证面节点不得验证自己产出的工件） | **静态可证明（直接自环面）**：E2321 验证面节点（check/gate ∪ human 标记）任一入边的生产者是它自己。**诚实边界**：间接自验证（A 产出→B 验证→A 又消费 B 的结论改写产出）v0.1 **不查**——提案 §8-4 开放问题，标注为已知缺口而非已保证 | 静态：af-dsl `validate/inv3.rs` | af-dsl M3；提案 B §5 INV-3 |
| **INV-4 评估器外部化**（评估 ground truth 对候选不可读） | **静态可声明（引用扫描）+ 运行时强制依赖执行面**：E2331 编译期扫描 `eval_input: true` 的 store 读者 ∉ {writer, 绑定 uses.unit 的 check 节点}——这只能证明**声明面无违规引用**；运行时若组件绕过声明面直读（如工具实现内嵌读文件），由执行面的读权限拦截强制（eval_input 槽的读者白名单在运行时生效） | 静态：af-dsl `validate/inv4.rs`；运行时：执行面读权限拦截 | af-dsl M3；ADR-010 §2 预判「INV-4 评估输入隔离=静态可声明（引用扫描）+运行时强制依赖执行面」 |

## 2. L1 执行契约（types/edges/emits/policies/构造有界性——提案 B §1.2 L1 标注项）

| 保证 | 标注 | 判定/强制点 | 证据锚点 |
|---|---|---|---|
| **typed 工件流**（边两端端口存在且类型相等；对象 schema 必住类型表） | **静态可证明**：E2201 边端口类型核对、E2205 未知类型名、E2202 输出发射核对、E1003 内联对象 schema 拒绝。**信封血缘的包装忠实性依赖可信组件（执行时包装器）**：端口类型写 `envelope<T>` 即信封，`from_node/artifact_type/step` 由运行时包装器填——编译期只核类型不验证包装内容 | 静态：af-dsl refs/shape；包装：执行面工件包装器 | 提案 B §1.2 types/edges 段 |
| **store 有界保留**（max_items/max_bytes 至少其一） | **静态可证明（声明存在性）+ 运行时可强制（截断执行）**：E2208 编译期拒绝无上界声明；截断真的发生由执行面强制（rolling_window 等策略执行） | 静态：E2208；运行时：执行面 store 实现 | 提案 B §1.2 stores 段 |
| **loop 有界性**（max_iterations>0、carried 有界、安全点必声明） | **静态可证明（声明面）+ 运行时可强制（迭代计数）**：max_iterations 必填>0、carried 至少一上界（承 af-graph CarriedState::is_bounded）、safety_points 缺失拒绝编译；运行时计数器单调、达上限触发 on_exhausted——由执行面强制 | 静态：af-dsl 形状/语义层；运行时：执行面循环驱动 | 提案 B §1.3 loop；af-graph ControlledLoop |
| **map 扇出上限**（max_fanout 可声明） | **静态可声明 + 运行时可强制**：max_fanout 可选；声明后由执行面并发控制强制 | 同上 | 提案 B §1.3 map；落地契约 §3.2 |
| **route 互斥且覆盖**（多路路由无需图分析即正确） | **静态可证明（构造性）**：§1.5 归一化算法构造性地保证 guard 两两不相交且并集为真（第 i 条显式排除前 i-1 条；default 取全否）——正确性由构造成立，不是分析结果 | af-dsl `route.rs`（lowering 复用同一函数，无第二实现） | 提案 B §1.5；af-compiler `lower.rs` |
| **CEL 保守子集**（谓词无函数调用、无搜索、根绑定受限、必为布尔） | **静态可证明**：E1051 解析（含 cel-parser panic 兜底）、E1052 算子白名单（15 算子）、E2203 根 ∈ 位置词表、E1053 布尔性——四判全在编译期。**运行时求值通道可信**：执行面按 CelRef.source 重编译求值（digest 缓存），panic 兜底承 af-graph predicate.rs | 静态：af-dsl `cel.rs`；运行时：执行面 predicate 通道 | 提案 B §1.4 |
| **预算熔断**（budgets 三账：维度/作用域/上限） | **运行时可强制**：probe（余额不足不开轮）→ charge（工具后结算）→ 终态 budget_exhausted 不透支不静默；计划级对账 merge_consumers。**凭证签发依赖可信组件**：voucher 的签发方/签名机制未定义（落地契约 §5.3 缺口 #1，占位 bool）——凭证真实性当前在 TCB 外无验证 | 运行时：af-meter BudgetLedger + af-harness probe/charge（落地契约 §5.2 全套既有语义） | 落地契约 §5；af-meter `budget.rs` |
| **终止条件**（stop[]：CEL 谓词 → 终态 outcome） | **运行时可强制**：事件流喂 StopEngine，latched 决策即终态；谓词本身过静态四判 | 运行时：af-stop + harness；静态：CEL 四判 | 落地契约 §5.1 熔断段 |
| **失败处置**（failures[]：分类→重试/路由/反馈/终态） | **运行时可强制**：四分类词汇表（F1-F4）+ 声明式覆盖；F1 供给瞬态层内退避对上层透明。**F1 的「可自愈」假设依赖可信组件（传输层/供给面）** | 运行时：harness 退避 + 调度重排队；词汇表：落地契约 §6.2 | 落地契约 §6 |
| **副作用恰好一次**（at-least-once 传输 + 业务幂等键 = exactly-once 效果） | **运行时可强制（幂等键机制）**：IntentKey 命名式（stable_id/node/unit/attempt），重放同键不重做外部操作，effect_replays/fresh 分开计数。**幂等键的唯一性由命名式构造静态保证**；传输层 at-least-once 是假设不是保证（MES outbox 先落盘再发送、删前崩溃会再送一次） | 运行时：harness IntentKey + af-mes outbox + 调度去重 | poc-temporal（activity 执行 2 次扣款恰好 1 次实证）；poc-ledger（outbox 三崩溃点收敛）；落地契约 §6.1/§7.2-5 |
| **逃逸舱记账**（L4 逃逸显式声明、失败分类账记账、占比警戒） | **静态可证明（记账存在性）+ 运行时可观测（健康度）**：E2210 四字段缺一拒绝；escape 进 IR `escapes` 表（一等记账位）；占比 >30% 警戒是运行期健康度指标，不拒绝编译 | 静态：af-dsl；IR：`IrBody.escapes`；运行时：健康度指标 | ADR-001 §3；提案 B §1.3 escape |
| **确定性编译**（同输入两次编译 IR 逐位一致） | **静态可证明（对编译器自身）**：全链路 BTreeMap/排序键/无时钟无随机无网络；六 golden 样例逐位断言 ×2 编译。这是**对编译器的测试义务**，不是对外的功能保证 | af-compiler `lower.rs` + golden 测试 | 提案 B §3.5；G2a 测试 |
| **拒绝式信封**（DSL 版本信封 / IR `ir_version` / 计划对象 deny_unknown_fields） | **静态可证明**：版本不符或未知键整份拒绝、body 不解析；装载即校验、失败路径点名不静默降级 | af-dsl `envelope.rs`；af-compiler `decode.rs`；计划对象（G2b 后） | af-harness decode_spec 先例；落地契约 §7.1 装载纪律 |

## 3. 可信计算基（TCB）四行表

| TCB 成员 | 被信任什么 | 不被信任什么（AFB 的对应防御） |
|---|---|---|
| **编译器**（af-dsl 校验 + af-compiler lowering） | 静态判定无漏判（校验器正确性）；lowering 保真（IR 与 AST 语义一致）；确定性（无隐藏状态影响输出） | 不被信任做运行时行为——编译产物自带全部约束声明，执行面按声明强制，不回调编译器；校验器自身的 bug 由 golden 回归 + 失败分类账兜底（测试是独立代理持有，ADR-007 §4） |
| **执行面**（af-execline/af-engine + harness 运行时） | 装配忠实（按 context.sections 装配、配额不超）；读权限拦截（eval_input 白名单）；预算 probe/charge 不透支；迭代计数与扇出上限；幂等键生成与重放去重；MES outbox at-least-once | 不被信任做策略制定（预算/终止/失败策略全部来自声明，执行面只执行）；不被信任自证合规——装配/扣费/拦截全留 trace 与 MES 事件，事后可对账 |
| **绑定组件**（packages/ 注册表：model_route / loop_policy / memory / tools / context_compaction / escape 实现） | 组件行为与其声明一致（effect_class 标注真实：Pure 不落盘、ExternalOnce 幂等；工具副作用同键可重放）；注册表 digest 完整（E9004 装载期核对） | 不被信任守图级不变量——写冲突由 INV-2 静态排除 + 执行面按 writer 路由兜底；组件失约可归因（digest + L4 记账 + effect_class 声明面），不能被预防 |
| **验证器**（check/gate 节点 + uses.unit 判定单元） | 判定输出与 resume/emits schema 一致（类型核对在编译期，E2201）；判定独立性（INV-3 静态保证验证面不是生成面的直接自证） | 不被信任写被验工件（验证面节点写目标工件 = E2321 面拒绝）；判定值的真实性（unit 是否真在验该验的东西）无法机器判定——只能靠 unit 组件契约与证据链（eval_sha256 位） |

## 4. 诚实边界汇总（本矩阵不宣称的）

1. **间接自验证不查**（INV-3）：v0.1 只判直接自环；A→B→A 的间接自验证是已知缺口（提案 §8-4）。
2. **装配忠实性不可静态证**（INV-1）：编译器只能证明「声明面完整」，运行时装配器的忠实性在 TCB 内，事后审计靠 trace。
3. **eval_input 只能拦声明面读法**（INV-4）：组件实现内嵌绕过（如工具代码里直接读文件系统）超出引用扫描视野，依赖执行面的沙箱/权限层（该层当前为占位，见落地契约 §2.3/§5.3）。
4. **voucher 签发机制未定义**（预算）：`signed: bool` 无密码学内容，签发方待对接会裁决（落地契约 §7.3 开放项 #1）。
5. **传输层 at-least-once 是边界不是保证**：所有「恰好一次」效果由幂等键构造达成（poc-temporal/poc-ledger 实证），不可假设传输层提供了它没承诺的东西。
6. **L4 逃逸舱内的行为不保证**：逃逸实现（任意代码执行等）只被记账不被约束——这是 L4 的定义（ADR-001 §3），AFB 的义务是「可归因」不是「可预防」。
