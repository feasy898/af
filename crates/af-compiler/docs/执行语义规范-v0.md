# 执行语义规范 v0（G2a 交付 · ADR-010 义务二）

- 版本：v0（2026-10-24，G2a 随 IR schema v1 一并交付；义务来源 ADR-010 §3「执行语义必须成文于 IR 层」；同日 fix2/P2-L08 勘误——§1.1/§1.2/§1.3 三处「编译期已保证」由 G2a 独立验证实测为高报（当时 stage 1 并未强制），随 af-dsl 三守卫校验（E2002/E2004/E2322）落地更新为已强制并引用实码）
- 地位：本文规定 IR v1 各构造的**操作语义**——执行面（af-execline/af-engine/harness）实现时的规范依据；与《保证边界矩阵》配套（哪里是保证、哪里是 TCB，见彼文）。
- 语义先于实现的既有裁决基础：落地契约 §5（预算执行与熔断）、§6（失败恢复）、§7.2（Tempo 裁决影响：订单语义由 af-engine + ledger + MES 承载）；poc-temporal 与 poc-ledger 的实测裁决（见各节引用）。
- 记法：`【强制】`=执行面必须实现且可测试；`【约定】`=v0 取的确定性约定（可裁决变更）；`【占位】`=v0 声明位，语义待后续裁决。

## 0. 总则（承落地契约 §6.2 恢复总则 + §7.2 裁决）

1. **计划对象自含**：无 workflow 引擎历史可回放，编译产物（IR→计划）单文件即编排真相；运行态只存在于盘上三账本（run_store / records.jsonl / mes_events）。恢复 = 重装计划 + 重读账本。
2. **终态即答案**：已终态的执行单元重复调用返回同一报告，不再触发模型调用（harness `run.rs` 既有语义）。
3. **重跑不覆写**：尝试序号单调递增（a1/a2/…），旧目录是复核证据。
4. **副作用恰好一次 = at-least-once 传输 + 业务幂等键**（§4）；不可假设传输层给任何更强承诺——poc-temporal 实证：activity 执行 2 次、扣款恰好 1 次，靠的是幂等键不是引擎。
5. **执行无隐式状态**：图遍历、迭代计数、扇出实例、预算余额全部可从三账本 + 计划声明重构。

## 1. loop（受控循环）

**结构**（IR `ControlledLoop`）：`body`（命名子图）+ `max_iterations` + `carried[]` + `safety_points[]` + `args` + `exit_when` + `on_exhausted`。

- **1.1 迭代边界【强制】**：`max_iterations > 0` 编译期已强制（缺失 → E1002 形状层拒绝；`= 0` → E2002 值域拒绝——fix2/P2-L08 起实装，af-dsl `validate/loop_guard.rs`；G2a 独立验证观察项 2 的原高报就此闭口）。运行时维护单调递增计数器 `iter ∈ [1, max_iterations]`；每完成一轮迭代（子图 entry 可达的全部节点终态化）后计数器 +1。达 `max_iterations` 且 `exit_when` 未命中 → 按 `on_exhausted` 收束：
  - `continue`：循环节点正常完成，`done: signal` 照常发射（样例 4/6：预算跑满取最优/换下一课程目标）；
  - `fail`：循环节点终态 `failed`（样例 2/5：QA 不通过耗尽轮次 = 失败；LangGraph `GraphRecursionError` 的声明式对应物）；
  - `keep_best`：取已完成的最佳迭代产出为 `done` 产物（v0【占位】：选择函数由绑定期组件契约定，IR 只保留枚举位）。
- **1.2 carried 重建【强制】**：`carried[]` 声明的 store 跨迭代携带，**且每项必须有界**（max_items/max_bytes 至少其一——E2002 值域拒绝，fix2/P2-L08 起实装，承 af-graph `CarriedState::is_bounded` 口径：`Some(0)` 视为已声明上界；与 E2211 覆盖性互补不重复）。每轮迭代开始时：
  - `lifecycle: iteration` 的 store **整体重建**（清空重置）；
  - `lifecycle: run`/`persistent` 的 store 保留前序内容，按声明的上界截断（滚动窗口：保留最近 max_items 条/预算 max_bytes 内）；
  - 未列入 `carried[]` 而被体内写入的体外 store 不存在（E2211 编译期已排除）——运行时无需防御。
- **1.3 安全点【强制】**：`safety_points` 非空编译期已强制（缺失 → E1002 形状层拒绝；为空 → E2004 空集合拒绝；且每项必须指向验证面节点——E2322，kind 三值承 af-graph `validate.rs` 语义原样：check→kind=check 节点、gate→kind=gate 节点、human→human 标记——fix2/P2-L08 起实装；路径悬空仍归 E2107）。每轮迭代**必须经过**至少一个安全点节点（check/gate/human）的判定输出，否则该轮不得计入完成——这是「循环受控」的运行时兑现（静态 DAG 豁免循环体的环，代价就是安全点必经）。
- **1.4 exit_when【约定】**：求值时机 = 每轮迭代内**验证面节点的 `passed`/emits 端口产出后**（`attempt` 绑定取最近一次验证输出）；求值为真 → 循环立即收束（当轮产出为终产物），不再消耗剩余迭代预算。求值走 CelRef 通道（digest 缓存编译产物）。
- **1.5 route 提前收束一轮【约定】**：体内节点的 route `goto: exit` 分支（归一化后守卫记在 `IrNode.route_exit_guard`，不产边）命中 → **本轮迭代提前收束**（当轮产出保留，下轮照常开始）——区别于 exit_when 的「整个循环收束」。`default: exit` 无规则型 exit 守卫时为结构性收束（无出边可走，本轮自然结束；早退语义由 loop 自身的 `exit_when` 承担，见样例 5 的 approve/ring 双层设计）。
- **1.6 args 隐式依赖【约定】**：`args` 的每个 `节点.端口[.字段]` 绑定构成一条隐式依赖边（计入 DAG）：引用的产出未就绪则本轮迭代该构造不启动；`input.字段` 绑定读整图输入。map 隐式形参 `item` 同理（§2）。

## 2. map（受控扇出）

**结构**（IR `MapSpec`）：`body`（命名子图，`graph_version` 已 stamp——**未版本化 map 体在 DSL 面不可能**，af-graph E2007 保留给 IR 直写路径）+ `over` + `max_fanout`。

- **2.1 运行时定基数【强制】**：`over`（`节点.端口` 或 `input.字段`）解析为 list（编译期 E2104 已核类型为 list）；元素数 N **运行时才确定**（对标 Airflow Dynamic Task Mapping）。N=0 → 空扇出，`done` 直接发射（聚合产物为空表）。
- **2.2 实例化与隔离【强制】**：每个元素实例化一份子图，经隐式形参 `item` 收元素。**实例间无横向边**——静态图就不存在实例间边（编译期保证），运行时不得引入实例间通信；实例写共享 store 被 E2312 编译期排除。样例 3 的 N 辩手互不可见即本条。
- **2.3 并发上限【强制】**：`max_fanout` 声明时，同时在飞的实例数 ≤ max_fanout（调度级并发控制，落地契约 §3.2 gates/limits 通道）；未声明 = 执行面默认并发（【占位】默认值待对接会裁决）。
- **2.4 聚合【约定】**：map 节点的 `from_body` 发射端口（如样例 3 `items: {from_body: debater.position}`）聚合全部实例的同名端口产出，**自动包 `list<>`**（类型推导规则与 af-dsl 同源）。聚合序【约定】：按**实例序**（`over` 的元素下标序）排列——不是完成序（完成序不确定，会破坏逐位可复现纪律；样本内 shuffle 由 `shuffle_seeded` 显式做且必须带 `seed_ref`）。部分实例失败时是否聚合部分结果：按 failures[] 的 class 处置（§5），`tool_error → next_iteration` 类不中止评估（样例 4）。
- **2.5 隐式入边【约定】**：体内节点 `consumes: {item: T}` 收隐式入边（元素本体）；对 item 的消费同样走 INV-1 装配（LLM 节点经 `from: arg, name: item` 段，样例 4 gen_a/gen_b）。

## 3. route（归一化守卫求值）

**结构**：DSL `route` 在 lowering 时归一化为 **边守卫**（`IrEdge.guard`，互斥且覆盖由构造成立）+ **节点 exit 守卫**（`route_exit_guard`，goto:exit 分支不产边）。归一化是纯文本重写，无搜索、无图分析（提案 B §1.5）。

- **3.1 求值时机【强制】**：路由节点完成（全部 emits 端口产出）后，对其**每条出边的 guard 各求值一次**（同一求值上下文；CelRef.digest 相同的守卫共享缓存编译产物）。guard 为真 → 该边投递。
- **3.2 互斥与覆盖【静态已证】**：guard_i 两两不相交（第 i 条显式排除前 i-1 条）且与 default 守卫的并集为恒真——**每条出边恰被一个守卫命中**，不存在零投递或双投递。执行面**不得**再做去重/仲裁逻辑（那是语义重复；守卫已互斥）。
- **3.3 exit 分支【约定】**：`route_exit_guard` 为真 → 本轮迭代提前收束（§1.5）。多条 exit 规则的联合守卫按文档序析取（`g1 || g2`）。
- **3.4 词汇表【静态已判】**：守卫 CEL 过保守子集四判（E1051/E1052/E2203/E1053）；`<节点 id>` 根的可见范围含节点自身（可写 `qa.passed` 亦可写裸 `passed`）。

## 4. 边投递（at-least-once + 幂等键）

**结构**（IR `IrEdge`）：`from.output → to.input` + `checkpoint` + `guard`。边 = 工件引用，不是消息队列。

- **4.1 投递语义【强制】**：边投递 **at-least-once**——执行面崩溃恢复后可能重投（MES outbox 先落盘后发送、删前崩溃会再送一次，poc-ledger 8/8 实证跨库窗口；调度级跨宿主并集去重防重复消耗）。消费者的入边端口消费必须**幂等**：同工件重复到达不重复触发节点（节点激活条件 = 全部必需入边就绪，重投不改就绪集）。
- **4.2 幂等键【强制】**：副作用级幂等键命名式（IntentKey 泛化）：`{stable_id}/{node_id}/{unit_id}/{attempt}`——键由**声明面机械生成**（静态保证唯一性），重放同键不重做外部操作，`effect_replays/effect_fresh` 分开计数（harness 既有语义，落地契约 §6.2 recovery.idempotency_key）。图级「恰一次投递效果」由此构造达成。
- **4.3 guard 边【约定】**：守卫为假的边不投递（该工件对本消费者不可见——不是丢弃，是未发生）。守卫求值失败的处置：按 `failures[]` 的 class 处置（求值错误归 environment_failure 面，F2）。
- **4.4 checkpoint【占位】**：`checkpoint: true` 声明该边携带快照语义（LangGraph checkpointer 对应位）。v0 只保留声明位，快照的存储/恢复语义由执行面承载（落地契约 §6.3 缺口：无结构化节点检查点对象——开放项）。
- **4.5 envelope 血缘【约定】**：端口类型 `envelope<T>` 的边，运行时包装器填 `from_node/artifact_type/step` 三血缘位（类型在编译期已核；包装忠实性在 TCB，见保证边界矩阵 L1-typed 工件流）。

## 5. 重试与补偿

**分类基础**：失败四分类词汇表（落地契约 §6.2，F1-F4）+ `failures[]` 声明式覆盖（class → retry/route/feedback/fallback_route/terminal/outcome）。

- **5.1 F1 供给瞬态【强制·层内透明】**：传输/限流/密钥过期类，harness 层内指数退避重试（HTTP ≤5 次、401 单次重取），对上层透明仅计数。重试不消耗图级重试预算（它们不是节点失败）。
- **5.2 F2 环境失败【强制】**：setup/取证/判分桥接失败 → 节点记 partial，按 `node_retry`（max_attempts 默认 3 / requeue_delay 默认 600s）重排队；连续失败达上限 → 终态需人工（`terminal_needs_human`，调度 FAIL_LIMIT 语义）。
- **5.3 F3 执行终态【强制·不重试】**：六种 RunStatus 终态语义已终态，不重试；`failures[].terminal: true` 的类（budget_exhausted 等）直接按 `outcome` 落终态账。预算耗尽语义【强制】：开轮前 probe 拒绝 → 节点终态 budget_exhausted，不产生第 N+1 次模型调用；已产生消耗保留（拒绝不回滚，af-meter 语义）。
- **5.4 F4 判定完成【强制】**：verdict 落账，进入依赖解锁（下游边投递）。
- **5.5 声明式路由【约定】**：`route: same_node`（节点内继续，配 `feedback` 观察回灌）/ `next_iteration`（循环下一轮，样例 4/6 的 gate_refused）/ 节点 id（跳转，E2204 编译期已核存在）。`fallback_route`：retry 耗尽后的降级跳转（样例 3：限次重解析仍败 → 裁决器）。
- **5.6 补偿【约定】**：跨库/跨服务一致性**不假设原子提交**（poc-ledger：WAL 下跨文件无原子性是硬边界，8/8 分裂实测）——补偿写法 = outbox（本库事务内「业务行+信箱行」→ 对端幂等落回执 → 标 done），三崩溃点注入全部收敛到「账=1、回执=1、真实执行=1」。执行面一切跨账本写遵循此模式；图级补偿动作（撤销已发射工件）v0 不提供（发射即事实，修正走后继工单 supersede——`WorkOrder::successor`，落地契约 §6.2 总则 5）。
- **5.7 断点续跑【强制】**：递交声明与首启逐项相等才准续跑（harness check_decl 语义）；余额从落库 current 恢复，不重复扣历史；`Breakpoint::BeforeTurnCommit`（副作用已落、行未提交）是续跑安全界。

## 6. 预算执行（引落地契约 §5.2，全条照搬为 IR 语义）

1. 节点启动顺序强制：`attach_voucher(signed)` → `release` → `start`；
2. 每轮模型调用前 probe、工具后 charge；熔断 latched 即终态 stopped，critical trace 留痕；
3. 续跑余额以库为准，递交声明不符即拒绝；
4. 计划级收尾对账 `sum(node_ledgers.spent) <= voucher.amount`（merge_consumers 语义），超限=记账事故上报（v0 只上报不自动处置）；
5. `budgets[]` 的 scope（plan / node:\<id\> / loop:\<id\> / map:\<id\>）由 stage-4 计划生成时展开为节点级 BudgetRef 实例集（IR 保留 scope 原样串）。
