# ADR-007: TDD 开发规约——红-绿-重构、小模块自包含可审计

- 状态：已裁决（2026-10-24，编排者；用户指令固化）

## 裁决

1. **先红后绿再重构**：每个模块的第一笔提交必须包含失败的测试（或可执行验收用例），随后最小实现转绿，再重构。禁止"先写实现后补测试"。
2. **小模块快跑**：单模块交付周期内可独立 `cargo test` 通过；crate 内按模块切分任务包，每包 ≤1 天工作量尺度。
3. **自包含可审计**：每个模块交付时带三件——测试文件（含拒绝用例与预期错误码）、模块 RESULT.md（做了什么/证据/遗留）、错误码契约（稳定码 + 精确信息，沿用 E2001/DI1001 风格）。
4. **实现/验证分离**（宪法 R6）：实现代理与验证代理必须是不同代理；测试与判分代码由测试代理独立持有，实现代理不可改。
5. **任务包五要素**（模板见 计划/任务包模板-第二阶段.md）：目标 / 必要上下文 / 约束（引用宪法条款与 ADR）/ 验收标准（可执行测试）/ 禁止事项。**不含可执行验收标准的任务包不得下发。**
6. LLM 产出的任何草稿（m3.1f 机制卡、翻译草稿）只是输入，通过与与否由确定性编译器与测试套件裁定（宪法 C7/R4）。
