# ADR-010: 专家高维意见的讨论与吸纳裁决

- 状态：已裁决（2026-10-24，编排者；依据运营者转达的专家意见及"讨论后吸纳、不默认接受"指令）
- 原则：逐条给出 接受/部分接受/暂缓 + 理由 + 可执行动作；与既有裁决（宪法/使命指令/ADR-001~009）冲突处以优先序裁决（宪法 > 任务中立 > 向后兼容 > 功能丰富度 > 开发速度）。

## 逐条裁决

### 1. 重新设定竞争基线（vs 通用配置语言+Schema+策略引擎+工作流系统组合）——**接受，列入 G5 报告义务**
G0 矩阵是使命指令规定的三框架口径；专家指出的组合基线确实更强。但我们的差异化物已具体存在且组合基线同样缺位：**编译期 L0 不变量**（写者唯一/验证分离/评估外部化的静态判定——CUE+策略引擎组合无 agent 图语义，无法静态判跨节点写冲突）、**typed 工件流+血缘信封**、**逃逸舱记账**、**任务中立性机器检查**。动作：G5 交付报告新增《保证对比矩阵》节——逐保证列 AFB vs「CUE+CEL+策略引擎+通用工作流」组合的提供成本；每条标"仅 AFB / AFB 显著低成本 / 组合同等"。

### 2. 严格区分三种保证（静态可证明/运行时可强制/依赖可信组件）+ 可信计算基——**完全接受，立即执行**
这正是我们诚实性的短板。动作：G2 af-compiler 的 IR 设计任务包**必含**《保证边界矩阵》：每条 L0/L1 保证标注三类之一 + TCB 表（编译器被信任什么/执行面被信任什么/绑定组件被信任什么/验证器被信任什么）。预判标注：INV-2 写者唯一=静态可证明；INV-4 评估输入隔离=静态可声明（引用扫描）+**运行时强制依赖执行面**（eval_input 读权限运行时拦截）；INV-1 上下文装配=静态可证明声明面、装配忠实性依赖执行面。

### 3. IR 与执行语义先于语法；golden 是卫生非护城河；跨后端语义一致性套件——**部分接受**
接受：执行语义（并发/重试/幂等/补偿/超时/副作用/状态版本化）必须成文于 IR 层。澄清：golden 从未被当护城河——它是宪法 C10 的回归纪律；且"语义先于语法"已是我们的实际路径（落地契约 §5/§6 与 poc-temporal/poc-ledger 裁决先行，语法提案引用之）。动作：G2 IR 设计必含《执行语义规范》节（每构造的操作语义：loop/map/route/边投递/重试幂等补偿）；影子对拍已有三维度扩展为**语义一致性套件**（G5 收编，多适配器时代自动成为跨后端一致性测试）。

### 4. L0 应约束目标性质而非固化实现方式——**接受其批评，v0.1 范围裁决维持，v0.2 开放机制多元**
专家说对了要害，且有我们自己的一手证据：AutoGen 草稿被迫把 Topic 多写者改写为 relay 单写者、Agensh worker 池共享板别扭——**翻译的是机制而非只保性质**。但使命指令 §2.4 已明言机制可随拓扑变化（"集中式由编排器强制；去中心化由原子合并协议强制"），v0.1 实现取单写者=集中式形态的最简可判定形式，且 v0.1 范围本就是 fallback=集中式+验证瓶颈。裁决：**v0.1 不动**（避免 G3 中途改语义）；**v0.2 高优议题**：stores 增加声明式"原子合并协议"机制（merge operator 声明，性质=串行化不变、机制=多元），由 AutoGen/Agensh 翻译痛点实证驱动。INV-2 在保证边界矩阵中拆两层：性质（无并发写冲突）+ v0.1 机制（单写者）。

### 5. 契约覆盖 capability/effect/provenance/trust（一等 IR 位）——**完全接受，立即执行（现在最便宜）**
部分资产已在：af-harness ToolDecl.effect_class（Pure/Persist/ExternalOnce）、af-credential Cedar+biscuit（capability 衰减）、envelope<T> 血缘+eval_sha256（provenance）、eval_input（trust 边界）。动作：G2 IR schema 为四者留**一等字段**（node.capability_refs / tool.effect_class 直通 / artifact.provenance / trust 注记），v0.1 可只允许默认值——位置先占住，避免日后破坏性变更。

### 6. 收窄通用性宣称（甜点=可审计、受治理的生产型 Agent 系统）——**接受，定位声明写入正本**
与我们自己的诚实分级一致（ADAS/AFlow 元循环=逃逸；拓扑选择器不设信仰）。动作：提案 B 正本引言（G2 随 IR 文档一并）加定位声明：AFB 面向受治理生产系统的定义与编译，开放式自进化 agent 的描述不是目标场景（其机制经 L4 逃逸记账接入）。

### 7. 更换成功判据（拦截事故/减少治理胶水/跨后端语义/长期资产化）——**接受为阶段级判据；G3 继续按使命指令完成**
15 目标对齐证明的是表达覆盖，不是开发必要性——同意。但它同时是回归语料库与失败分类账的生成器（账本本身是一等资产）。动作：第二阶段验收新增两个可测读数：**治理胶水对照**（旧体系 factory-sched+mcode-dispatch+bench-mes 代码行数/记账点数 vs 新执行面，影子对拍期采集）、**真实拦截记录**（门控拒绝/预算熔断/安灯触发各≥1 次真实事件入 MES）；第三阶段章程修订时并入专家判据。
